## Gift Codes for Free 30-Day Subscriptions

### Overview
Add a redeemable gift-code system. Codes can be generated by you (creator) or by company admins from their dashboard. Each code unlocks one user with a free 30-day subscription at a chosen tier (Silver/Gold/Platinum), single-use, full access. Near expiry, the user is prompted to convert to a paid plan.

### User-facing changes

**1. Pricing page (`src/pages/Pricing.tsx`)**
Below the three plan cards, add a `GiftCodeRedeem` section:
- Heading: "Got a gift code?"
- Input + "Redeem" button
- On success: toast + redirect to `/dashboard`
- On error: inline message (invalid, expired, already used, not logged in → push to `/auth`)

**2. Dashboard → new "Gift Codes" card (`src/components/dashboard/GiftCodesCard.tsx`)**
- "Generate code" button → dialog: pick tier + optional note → creates code, shows it with copy button
- Table of codes you've generated: code, tier, status (unused/redeemed), redeemed-by email, created date

**3. Subscription expiry prompt**
`useSubscription` already exposes `currentPeriodEnd`. Add a banner in dashboard layout when a gift-code subscription has ≤5 days left, linking to `/pricing`.

### Backend

**New table: `gift_codes`**
- `code` (text, unique, format `GIFT-XXXXXX`)
- `tier` (text: silver/gold/platinum)
- `created_by` (uuid → auth.users) — null = created by you via SQL
- `redeemed_by` (uuid, nullable), `redeemed_at` (timestamptz, nullable)
- `expires_at` for the *code itself* (optional, default null = never expires until redeemed)
- `note` (text, optional)
- RLS: creators can see/insert their own codes; service role full access. No public reads.

**DB function: `generate_gift_code()`** — returns unique `GIFT-XXXXXX` string (same pattern as `generate_company_code`).

**DB function: `redeem_gift_code(p_code text)`** (SECURITY DEFINER)
- Validates auth + code unused
- Marks code redeemed
- Upserts `subscriptions` row for current user: `subscribed=true`, `tier=<code.tier>`, `current_period_end = now() + 30 days`, `stripe_customer_id=null`, `price_id='gift_<tier>'`
- Returns tier + expiry

**Edge function: none required** — pure DB. Frontend calls `supabase.rpc('redeem_gift_code', ...)`.

**Email**: trigger `welcome` (or new `gift-redeemed`) email via existing `sendEmail` helper on successful redemption.

### Interactions with existing subscription logic
- `useSubscription` first checks Stripe via `check-subscription`. For gift users there's no Stripe customer → it falls back to the `subscriptions` row, which already works. ✅
- Gift subs won't be re-overwritten by `check-subscription` because the upsert there only runs if Stripe returns a customer.
- Tier-limit triggers (`get_active_tier`) already read from `subscriptions` — gift users get the right limits automatically. ✅
